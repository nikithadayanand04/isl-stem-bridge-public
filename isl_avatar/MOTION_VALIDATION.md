# Motion fidelity validation

How the project measures whether the avatar reproduces the recorded signer, what the numbers
mean, and what they cannot tell you.

> **Geometric similarity is not linguistic correctness.** Every number here compares the avatar
> with landmarks *tracked from* the source video. A sign can pass every check and still be wrong
> ISL: the tracking may be wrong, or the rig may change how the sign reads. Only a qualified ISL
> interpreter can approve a sign. There is deliberately **no overall "accuracy %"**.

Current results for every sign: [reports/VALIDATION_SUMMARY.md](reports/VALIDATION_SUMMARY.md),
generated by `python3 tools/validation_summary.py`. Per-sign detail is in
`reports/v2/<sign>/report.md`, with plots.

## 1. Recording and tracking quality (`tools/motion_qc.py`)

Run on the raw extraction, before anything is baked.

| Check | Rule | Effect |
| --- | --- | --- |
| Body tracked | ≥ 95% of frames | fail below |
| Face tracked | ≥ 90% of frames | fail below |
| Signing hand lost | ≤ 3 frames in a row | fail above. A resting hand does not count as lost. A **depth-flipped** frame does. |
| Gap severity | `critical` if the hand was moving or holding, `transition` if not | reported |
| Depth flips | palm normal jumps > 100° between tracked frames; a stretch of ≤ 5 frames facing away from the stable neighbouring stretch | counted as lost, interpolated in the bake |
| Recording | ≥ 24 fps, ≥ 720 p, brightness ≥ 60/255, hand sharpness (Laplacian variance ≥ 60) | warnings only |

Failures are never patched. The sign needs a clearer recording. A team-approved exception is
possible only as `motion_qc = pass_exception` with a written **QC EXCEPTION** note in
`registry/signs.csv`, and `check_registry.py` refuses an exception without one.

**Why depth flips count as lost.** From one camera, a hand and its front-to-back mirror image can
look the same. MediaPipe sometimes picks the wrong one for a frame or two: the palm appears to turn
about 160° in 40 ms, which no hand can do. Every joint is wrong in such a frame, so it is treated
exactly like a frame where the hand was not found.

## 2. Retargeting checks (during the bake)

| Check | What happens |
| --- | --- |
| QC re-run | The baker re-runs today's QC and refuses a failing clip, unless a documented exception is passed. |
| Anatomical joint limits | A finger bone turning beyond its range relative to its parent (thumb 70/70/90°, fingers 105/115/90°) is limited. The count and the worst case are printed. |
| World-only hand shape | Frames with only image landmarks are interpolated instead of mixing two coordinate systems. |
| Contact | Fingertip contact from the raw data is enforced on the avatar (stop at 5 mm, eased over 3 frames). |
| Thumb overlap | Thumb skin inside a finger is reduced to at most 1 mm where a turn of up to 25° per joint allows; the log lists frames corrected and what is left. |

## 3. Geometric comparison (`tools/animation_validator.py` + `tools/motion_report.py`)

The baked clip is sampled in Blender: 21 hand points per hand, shoulders, elbows, wrists, head
rotation and face values. It is compared with the source, frame by frame. Source frame *i* is
avatar frame *i + 1*, since Blender frames start at 1.

| Measure | How | Why this way |
| --- | --- | --- |
| Finger flexion | Angle at each of 15 joints per hand (0° = straight), avatar vs source | Independent of hand size and rig |
| Finger spread | Angle between neighbouring fingers | Handshape openness |
| Palm orientation | Palm frame relative to the chest frame, angle between avatar and source | Removes whole-body turn |
| Wrist / elbow position | Offset from the shoulder centre in the chest frame, scaled: sideways by shoulder width, down by torso length, up and forward by arm length | The same scaling the retargeting uses, so a sign at the chest stays "at the chest" on a different body |
| Contact | Fingertip–fingertip distance below 10% of shoulder width, in source vs avatar | Touch is phonologically important |
| Speed | Correlation of wrist speed over time | Rhythm and movement dynamics |
| Face | Mean absolute difference of the 52 face values after the same neutral calibration the baker applies | Measures the bake itself |
| DTW | Wrist trajectory aligned in time | **Diagnostic only**: it can hide timing errors, so it never decides pass/fail |

### Pass limits (`GEOMETRIC_LIMITS` in `tools/motion_report.py`)

| Check (per tracked hand) | Limit |
| --- | --- |
| Finger flexion error, median | ≤ 5° |
| Finger flexion error, 90th percentile | ≤ 15° |
| Palm orientation error, median | ≤ 10° |
| Palm orientation error, 90th percentile | ≤ 25° |
| Wrist position error, median | ≤ 0.10 of the body measure |
| Source contact frames missing on the avatar | ≤ 25% |

Each limit is checked and reported separately; a single failure fails the check. The limits sit
just above the tracker's own frame-to-frame noise on a still hand (a few degrees per joint), with
room for differences between the signer's hand and the avatar's.

**What the limits do not cover.** Joint limits and depth-flip removal deliberately make the
avatar differ from the tracked data in frames where that data is impossible. Those frames show up
as larger errors (the 90th-percentile checks). That is expected, and the bake log lists them.

## 4. Whole-avatar checks

- **Rig** (`tools/rig_validator.py`, results in `reports/rig/`):
  - hierarchy;
  - test poses with close-up renders;
  - joint ranges;
  - skin interpenetration between fingers on every frame of every baked sign (depth from
    per-segment convex hulls), split into *skin contact* (≤ 2 mm, as real fingers press
    together) and *passing through* (deeper);
  - two impossible control poses that the checks must catch.

  See [AVATAR_RIGGING.md](AVATAR_RIGGING.md).
- **Face** (`tools/facial_validator.py`, results in `reports/face/`):
  - all 52 ARKit shapes: size, region and left/right symmetry;
  - eye gaze;
  - brows and lashes following the skin under them;
  - face clip in sync with body clip;
  - a render of every shape.

## 5. Baseline comparison

`reports/baseline/` holds the first pipeline's bake, measured with the same code. That bake used
heavy smoothing, image landmarks only, direction-only fingers and no joint limits. It fails the
geometric check on all 5 signs it covers. See [AUDIT_REPORT.md](AUDIT_REPORT.md).

## 6. Re-running everything

```bash
sh tools/bake_all.sh                    # bake + sample + report every passing sign, export the GLB
blender -b avatar/avatar_source.blend --python tools/rig_validator.py -- \
    --bone-map tools/bone_maps/mixamo.json --out reports/rig --renders
blender -b avatar/avatar_source.blend --python tools/facial_validator.py -- --out reports/face --renders
python3 tools/validation_summary.py     # reports/VALIDATION_SUMMARY.md
python3 -m unittest discover tests
```
